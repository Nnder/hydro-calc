# Сохранение ресурсов Nuxt

На VPS раздача `/_nuxt/` настроена напрямую через nginx из
`/var/www/athydro/shared-assets/_nuxt`. Архив содержит ресурсы сохранённых релизов.
`/_nuxt/builds/` проксируется в активный Nuxt с Cache-Control: no-cache.

`preserve-nuxt-assets.py` установлен как `/usr/local/bin/athydro-preserve-assets`.
Drop-in `/etc/systemd/system/athydro-nuxt.service.d/preserve-assets.conf` запускает
его через ExecStartPre из WorkingDirectory нового релиза с правами службы.
Скрипт копирует отсутствующие ресурсы атомарно до старта Nuxt; папка архива
принадлежит www-data. При публикации сохранять этот drop-in и общий архив.
Не удалять старые файлы одновременно с переключением релиза: открытые вкладки
могут продолжать запрашивать их.

Настройка добавлена 26.10.2026 после сообщения об ошибке загрузки JS.
500 из пользовательского скриншота не воспроизведена и в просмотренных логах
не найдена; изменение устраняет зависимость раздачи файлов от процесса Nuxt,
но не доказывает первопричину исходного сбоя.
Проверены HTTP 200 для четырёх JS из скриншота, главной и builds/latest.json,
HTTP 404 для отсутствующего файла, права запуска ExecStartPre и nginx -t.
